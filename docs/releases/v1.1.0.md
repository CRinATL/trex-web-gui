# trex-web-gui 1.1.0

The first release after 1.0.0: a better packet editor, a safer capture viewer, fixes to the behaviours the
release-candidate triage left open, every API route's error codes declared, and an `install.sh` that installs the
latest release with one command. The wheel is `trex_web_gui-1.1.0-py3-none-any.whl`, attached to the GitHub
release `v1.1.0`.

## What is in

- **Studio, packet editor**: the Presets dialog has one tab per preset, so Close no longer sits below a long
  scroll; a visible **New** button sits beside File, Templates and Presets; a layer the built bytes do not hold is
  titled `<layer> (not decoded)`, e.g. `DHCP (not decoded)`; `trex-web-gui/DHCP-DISCOVER` is a broadcast discover whose every layer decodes (TRex's
  own DHCP template has no options, so its DHCP layer never decodes); a field's byte range now ends where the next
  field starts, and the last field runs to the layer's end, so variable-size fields such as DHCP, BOOTP and TCP
  options show their true range; a preset refused while another tab is open marks its own tab with `!`. The
  guide's packet-editor sections are updated (#12, #13).
- **Studio, stream table**: the toolbar and the pager are spaced off the table frame (#11).
- **Capture viewer**: a clicked packet is dissected in the packet worker, under its 5 s call timeout and memory
  limit, instead of on the backend's scapy thread; a frame over 9 238 bytes is dissected that far and the rest is
  one Raw layer. A worker that is busy or closed answers 503 `engine_busy` or `engine_closed`. Live capture
  summaries read only a frame's first 2 048 bytes (#14).
- **Control and capture fixes**:
  - Stop overtakes an Apply's ARP resolve, which is now six short attempts; Pause, Resume and Update decide from the
    server; a stale foreign "port acquired" event no longer drops a port we hold; a cancelled Apply, ping or scan
    still refreshes (#7).
  - A TRex service's capture refuses Stop, Save and Remove with 409 `capture_busy`; Wireshark's process group is
    reaped in one locked place; a Stop while Wireshark is starting ends cleanly; the RPC console caps a published
    body at 64 KB; Save settles on its own result and offers Resume after a failure; Disconnect works during a
    Reconnect (#8).
- **API**: every route declares the `(status, code)` pairs it answers, listed under each route's Responses in
  `docs/api.md`, and a test keeps them equal to the code. The refusals raised outside `api/` are in one table
  under Errors. No route's behaviour changed (#6).
- **Installer**: `install.sh` is attached to the release; the command below prints the wheel's sha256 and
  the release page, downloads the wheel, checks it and, on a terminal, waits for Enter before installing (#9).
- Also in this release, with no change to what the application does: faster and steadier tests and CI (#10); the
  release tooling for patch releases (#5, #15); dependency updates (the python group in #2,
  certifi 2026.10.18 in #3, the npm dev group in #4).

## Install

```
curl -fsSL https://github.com/CRinATL/trex-web-gui/releases/latest/download/install.sh | sh
trex-web-gui serve
```

To pin this release, install the wheel directly:

```
uv tool install --python 3.12 https://github.com/CRinATL/trex-web-gui/releases/download/v1.1.0/trex_web_gui-1.1.0-py3-none-any.whl
trex-web-gui serve
```

Open the login URL it prints; for a browser on another machine it also prints the SSH tunnel command. The one-line
command replaces an installed 1.0.0; stop its `trex-web-gui serve` first. A
host without internet: the README's [Offline host](../../README.md#offline-host) section. A first stream, step by
step: [docs/howto-first-stream.md](../howto-first-stream.md).

## Supported

- TRex v3.08 in stateless mode, STL API 5.1 (the passive Monitor also shows what stateful runs publish).
- Python 3.12 or newer; tested on 3.12, 3.13 and 3.14.
- A Linux backend only; any current browser.

## Known limitations

New in this release:

- **Capture summaries read the first 2 048 bytes of a frame.** A DNS response larger than that lists as UDP/Raw
  in the capture list; the layer tree of a clicked packet still decodes it (up to 9 238 bytes).
- **The packet worker is shared.** The capture viewer's tree and the packet editor use one worker, so a capture
  click can hold an editor call for up to 5 s.
- In the packet editor, with IP options that need padding, the following layers' byte ranges are early by the
  pad.

Security posture ([SECURITY.md](../../SECURITY.md) has the detail):

- The backend binds `127.0.0.1` only; there is no `--listen` and no TLS. Reach it from another machine through an
  SSH tunnel.
- A per-launch token gates the API, but any local process of the same user that reads the printed URL can drive
  it. `.py` profiles and Scapy field expressions run as code on the backend host, by design (the UI says so).
- Logging out deletes only that browser's cookie; the token stays valid until the backend exits, so restart it to
  revoke a login URL someone else has seen.
- A profile child that calls `setsid()` escapes the process-group kill.
- The TRex daemon on port 8090 has no authentication; restrict it before using daemon control outside a trusted
  test network.

Known issues carried over from 1.0.0, each **unverified**: seen on the hardware host, with the cause not found.

- **A port left owned after `trex-web-gui serve` stops.** Once, after a Ctrl+C, the next trex-web-gui was refused a
  port still owned by the stopped one. **Re-acquire my ports** takes it back. The stop prints `Released port(s) …`
  or `Releasing port(s) … failed`; please report that line if it happens.
- **`Load failed` on Control.** A request that got no reply (Safari's wording), seen once over an SSH tunnel; the
  message names the request and asks whether `trex-web-gui serve` and the tunnel are up. The cause is not known.

Other limitations:

- **Drop rate is TRex's Tx minus Rx over all ports**, so traffic that does not come back to a TRex port reads as
  dropped. It is a loss figure only when the traffic loops back, through a device under test or a cable.
- The Events log is not restored after a page reload.
- On a `linux_based` TRex, a VLAN set and then cleared on a port stops it answering ARP until TRex restarts.
- Service mode is changed per port on Control > Config; the Dashboard's service-mode bar and Capture > LLDP can
  turn it off.
- A saved test setup keeps the Dashboard tab, interval and layout, not its Y axis choice.
- The guide's screenshots were taken for 1.0.0; the packet editor's Presets dialog and the stream table's spacing
  have changed since.

## Deviations

Where trex-web-gui differs from the tools it replaces:

- Keyboard accelerators: Ctrl+Shift+C, Ctrl+Shift+P, Esc and Enter, and the stream keys (Ctrl+C/V, Del,
  Alt+↑/↓) are built; Ctrl+Shift+D is not, and Ctrl+Q is dropped (the browser owns it).
- A real command line replaces the old Java properties: `--server`, `--data-dir`, `--port`, `--monitor`,
  `--monitor-only`, `--daemon-port`. There is no `--listen` (loopback only, above).
- More than one profile on a port is shown read-only; full multi-profile control is planned.
- One application in the browser instead of three desktop tools; the backend runs on Linux only.
