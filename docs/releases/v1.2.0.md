# trex-web-gui 1.2.0

A new EMU page for the TRex emulation server, and Turn service mode off in amber. The installer is unchanged from
1.1.5.

The wheel is `trex_web_gui-1.2.0-py3-none-any.whl`, attached to the GitHub release `v1.2.0`.

## What is in

- **EMU page** (`/emu`): drives the TRex emulation server (`trex-emu`, RPC port 4510) beside the stateless
  session, on its own connection.
  - It lists the server's namespaces (port, VLAN tags, clients, plugins, and whether this app added them), the
    clients of a namespace, paged, and the counters of the server, a namespace or a client, with **Hide zeros**
    and a **Clear** baseline kept in the browser.
  - **Inspect** reads an EMU profile (`.py`) on the backend host: its tunables, namespaces, clients, plugins and
    vports, and warnings. **Load…** replaces everything on the EMU server with the profile, at a rate limit you
    set; **Remove all…** empties it. Both ask first and name what the server holds now, and ask for a second
    acknowledgement when it holds namespaces this app did not add.
  - Start TRex with `--emu` (the README's "EMU" section has the flags, and the **TRex daemon…** dialog can add
    it). The page's guide is [docs/gui-guide.md, 11a](../gui-guide.md#11a-emu).
- **Turn service mode off is amber.** On the Dashboard's service-mode bar and on Capture > LLDP it was green, the
  colour of Start, beside the red Stop LLDP monitor. It changes a port's mode and stops nothing, so it now takes
  the amber of the service-mode badge it clears. Turn service mode on stays green.
- For contributors: `AGENTS.md` has two new conventions (a test fails when the line it protects is deleted; data
  tied to a connection or server generation is dropped when that changes). Every reply the test fakes give that
  was never recorded from a real server is now listed in `tests/fake/unrecorded.py`, and `make check` fails on
  one that is not; the EMU fake answers as the recorded `trex-emu` does.

## Install

```
curl -fsSL https://github.com/CRinATL/trex-web-gui/releases/latest/download/install.sh | sh
trex-web-gui
```

To pin this release, install the wheel directly:

```
uv tool install --python 3.12 https://github.com/CRinATL/trex-web-gui/releases/download/v1.2.0/trex_web_gui-1.2.0-py3-none-any.whl
trex-web-gui
```

- Open the login URL it prints. For a browser on another machine, it also prints the SSH tunnel command.
- **Upgrading from 1.1.5 or earlier:** stop the running backend, then run the same one-line command.
- If the shell says `command not found`, open a new terminal or run the `export PATH=…` line the installer
  printed, or run `~/.local/bin/trex-web-gui`.
- A host without internet: the README's [Offline host](../../README.md#offline-host) section.
- A first stream, step by step: [docs/howto-first-stream.md](../howto-first-stream.md).

## Supported

- TRex v3.08 in stateless mode, STL API 5.1 (the passive Monitor also shows what stateful runs publish).
- Python 3.12 or newer; tested on 3.12, 3.13 and 3.14.
- A Linux backend only; any current browser.

## Known limitations

New in 1.2.0:

- **The shipped `trex-emu` v3.08 crashes** (the server is gone until it is restarted) when a namespace with the
  `ipfix` or `tdl` plugin at namespace level is removed, and when a client with `mdns` is added to a namespace
  without `mdns`. trex-web-gui refuses to load such a profile, and asks for an acknowledgement before it removes
  such a namespace it did not add. `ipfix` on a client, as in the stock `simple_ipfix.py`, is fine.
- **EMU has no authentication and no ownership.** Anyone who can reach port 4510 can read and change every
  namespace, and another tool can change the list under the page. Firewall the port or use an SSH tunnel (the
  README's "EMU exposure" section).
- **A load that fails part-way leaves a partial profile on the EMU server.** The page says so; load the profile
  again.
- **EMU is tested on the AF_PACKET test guest only.** On hardware NICs, TRex may need `--software` with `--emu`,
  and the port may need filtered service mode (mask 29); neither is verified on hardware.

Carried over from 1.1.4:

- **A stopped TRex server is told apart only on the backend's host.** With TRex on another host, or no server
  process seen at connect, a loss still waits for 12 s of silence and says the server may have stopped or the
  network may be down.

Carried over from 1.1.3:

- **The EVPN-VXLAN preset sends the data plane only.** TRex stateless mode holds no BGP session, so no EVPN
  routes are sent, and a switch that admits VXLAN only from VTEPs it learned over BGP may drop the traffic.
- **A GENEVE layer under UDP's default source port, 53, shows as `GENEVE as DNS`** (or `GENEVE as Raw`): Scapy
  reads those bytes as DNS first. Set the source port to any other value.

Carried over from 1.1.2:

- **A command run over `ssh` may not find `trex-web-gui` by name.** With bash and Ubuntu's `~/.bashrc`,
  `ssh <host> trex-web-gui` runs a shell that stops reading `~/.bashrc` before the line that adds `~/.local/bin`,
  so it answers `command not found`. Log in first, or give the full path, `ssh <host> '~/.local/bin/trex-web-gui'`.

Carried over from 1.1.1:

- In the Connect and Payload dialogs the unsaved-changes list opens outside the dialog, so a screen reader that
  honours `aria-modal` may not reach it; the ⓘ notes behave the same way.

Carried over from 1.1.0:

- **Capture summaries read the first 2 048 bytes of a frame.**
  - A DNS response larger than that lists as UDP/Raw in the capture list.
  - The layer tree of a clicked packet still decodes it, up to 9 238 bytes.
- **The packet worker is shared.** The capture viewer's tree and the packet editor use one worker, so a capture
  click can hold an editor call for up to 5 s.

Security posture ([SECURITY.md](../../SECURITY.md) has the detail):

- The backend binds `127.0.0.1` only; there is no `--listen` and no TLS. Reach it from another machine through an
  SSH tunnel.
- A per-launch token gates the API, but any local process of the same user that reads the printed URL can drive
  it.
- `.py` profiles and Scapy field expressions run as code on the backend host, by design (the UI says so).
- Logging out deletes that browser's cookie and closes every open WebSocket of the backend, every tab's. The
  token stays valid until the backend exits, so restart it to revoke a login URL someone else has seen.
- A profile child that calls `setsid()` escapes the process-group kill.
- The TRex daemon on port 8090 has no authentication. Restrict it before using daemon control outside a trusted
  test network.

Known issues carried over from 1.0.0, each **unverified**: seen on the hardware host, with the cause not found.

- **A port left owned after the backend stops.**
  - Once, after a Ctrl+C, the next trex-web-gui was refused a port still owned by the stopped one.
  - **Re-acquire my ports** takes it back.
  - The stop prints `Released port(s) …` or `Releasing port(s) … failed`; please report that line if it happens.
- **`Load failed` on Control.**
  - A request that got no reply (Safari's wording), seen once over an SSH tunnel.
  - The message names the request and asks whether `trex-web-gui serve` and the tunnel are up.
  - The cause is not known.

Other limitations:

- **Drop rate is TRex's Tx minus Rx over all ports**, so traffic that does not come back to a TRex port reads as
  dropped. It is a loss figure only when the traffic loops back, through a device under test or a cable.
- The Events log is not restored after a page reload.
- On a `linux_based` TRex, a VLAN set and then cleared on a port stops it answering ARP until TRex restarts.
- Service mode is changed per port on Control > Config. The Dashboard's service-mode bar and Capture > LLDP can
  turn it off.
- A saved test setup keeps the Dashboard tab, interval and layout, not its Y axis choice.
- The About screenshot shows 1.1.4: the screens were last shot before 1.1.5.

## Deviations

Where trex-web-gui differs from the tools it replaces:

- Keyboard accelerators:
  - built: Ctrl+Shift+C, Ctrl+Shift+P, Esc and Enter, and the stream keys (Ctrl+C/V, Del, Alt+↑/↓);
  - not built: Ctrl+Shift+D;
  - dropped: Ctrl+Q (the browser owns it).
- A real command line replaces the old Java properties: `--server`, `--data-dir`, `--port`, `--monitor`,
  `--monitor-only`, `--daemon-port`. There is no `--listen` (loopback only, above).
- More than one profile on a port is shown read-only; full multi-profile control is planned.
- One application in the browser instead of three desktop tools; the backend runs on Linux only.
