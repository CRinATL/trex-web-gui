# trex-web-gui 1.5.0

Controls have one look in 1.5.0, with a Density setting. The Dashboard's Streams and Latency tables fit their column,
and the chart choices survive leaving the page. The Traffic tab shows the measured rate. A daemon Stop beside a
hand-started TRex no longer reports "stopped" for a TRex that is still there. The installer is unchanged from 1.4.1.

The wheel is `trex_web_gui-1.5.0-py3-none-any.whl`, attached to the GitHub release `v1.5.0`.

## What is in

- **One look for controls.**
  - Buttons, text inputs and selects share one minimum height (32 px), padding, border and radius in every
    theme, with the page's font. Their borders keep 3:1 contrast in Light, Dark and High contrast.
  - Settings > Appearance has a **Density** choice: **Comfortable** (32 px controls) or **Compact** (26 px, for more
    rows on a small screen). It is kept in this browser, applied before the first paint and needs no Save. It is
    offered on the `--monitor-only` Settings page too.
- **One solid run button per Control toolbar group**: the step to take. That is Stop while a port transmits,
  Resume while it is paused, and Start all only while no port you own runs; the others are quiet.
- **Dashboard Streams and Latency tables fit their column at 1400 px.**
  - Streams shows Chart, PG ID, Type, Tx/Rx pps, Loss and Loss/s; **Columns ▾** adds the bit rates (L1 and L2)
    and the packet and byte counters.
  - Latency's Last … Last-9 are behind **Show history**, appended after Errors.
  - **Full-width table** stacks the chart under the table.
  - Numbers and their headers are right-aligned.
- **Dashboard chart choices survive leaving the page.** Each Overview chart's series, the Streams and Latency chart
  metrics and intervals, the columns, history and full width are kept in this browser. The Latency histogram's PG
  ID is kept across page switches and reset on a new connection.
- **A test setup saves the Dashboard's Y axis choice** (Fit or From 0); setups saved before read as Fit.
- **The Traffic tab shows `Measured now: Tx … · L2 … · L1 …`** under the ×1 line. It is the port's live Tx rate
  from the same stats as the Dashboard, with dashes until stats arrive after a reconnect.
- **Daemon Stop and Force stop.**
  - Force stop always kills the daemon's run, whether or not this backend started it. While the daemon is Idle, a
    Force stop is refused before any port-owner read.
  - A stop beside a hand-started TRex waits for the daemon's TRex to leave the process list, then probes the
    command port. If a TRex still answers there, the Run tab says so and names the TRex processes still listed,
    and Control keeps its session.
  - A stop the daemon could not confirm, because the daemon stopped answering after the stop was sent, says so,
    rather than "TRex is still running after the stop". The daemon's error shows too.
  - The second confirmation of a Force stop says a stateful (`-f`) run has no command port only when the backend's
    refusal says so; a `-i -f` command line reads as stateless.
  - On the daemon's Config tab, an error on a whole object (`memory` must be a mapping) shows inside that fold.
- **Editor.**
  - The stream table is a grid the keyboard alone can select in:
    - ↑/↓, Home and End select a row;
    - Shift extends the selection from its anchor;
    - Ctrl moves the active row (dashed outline) alone;
    - Space adds or removes the active row.
  - Duplicate of an entry linked to a `.py` offers **As a JSON profile**. The copy is backed by its own JSON, so
    Control assigns the edited streams. It is a snapshot: it has no tunables, and later changes to the `.py` do not
    reach it.
  - Simulate shows a dash for Total packets when any chain has no total (a continuous stream, or a loop forever),
    never a sum that counts the endless chain as 0.
- **Smaller fixes.**
  - The status bar keeps `trex-web-gui <version>` and its buttons on one line, wraps a long message, and in a
    narrow window moves them to a line of their own instead of overflowing. Its plain buttons show a hover.
  - The Test setups dialog is up to 40 rem tall, so a two-port setup's detail fits at 900 px.
  - Export and Import settings, and a capture file's Download and Delete, no longer touch.
  - Escape in the Columns ▾ panel returns focus to the Columns button.
- **Running as a service:** the README's "Run it as a service" and `docs/trex-web-gui.service` add
  `loginctl enable-linger`, so the user unit keeps running after you log out.
- **The GUI inventory's and the first-stream HOWTO's screenshots are re-shot** for the control look and the
  measured rate.

## Install

```
curl -fsSL https://github.com/CRinATL/trex-web-gui/releases/latest/download/install.sh | sh
trex-web-gui
```

To pin this release, install the wheel directly:

```
uv tool install --python 3.12 https://github.com/CRinATL/trex-web-gui/releases/download/v1.5.0/trex_web_gui-1.5.0-py3-none-any.whl
trex-web-gui
```

- Open the login URL it prints. For a browser on another machine, it also prints the SSH tunnel command.
- **Upgrading from 1.4.1 or earlier:** stop the running backend, then run the same one-line command. From 1.3.1
  or earlier, also:
  - Old `/studio` and `/studio/packet` bookmarks redirect to `/editor` and `/editor/packet`.
  - The README's section anchors changed: `#quick-start` is now `#first-launch`; `#before-you-start` is now
    `#what-you-need`, under `#getting-started`; the other ways to install, `#pin-a-version` and `#older-releases`
    moved to [docs/install.md](../install.md); `#offline-host` is kept.
  - A stock profile pick that shares one `.py` with several library entries shows the entry name of the slug sent;
    a path typed by hand shows the file name.
- **What 1.5.0 changes:**
  - The Dashboard's Streams bit-rate and counter columns, and Latency's Last … Last-9, are hidden at first:
    **Columns ▾** and **Show history** bring them back. The Streams chart's Metric select still offers the bit
    rates.
  - API changes ([docs/api.md](../api.md)):
    - `POST /api/daemon/stop` adds `confirmed`, `other_pids` and `still_answering` beside `running` and `stop_s`;
      `running: true` with `confirmed: false` means the stop could not be confirmed, not that TRex is still running.
    - A 409 `owners_unknown` body may carry `stf: true`.
    - `POST /api/studio/profiles/{slug}/duplicate` takes an optional `as_json` (false when absent) beside `name`.
    - A test setup's `dashboard` carries `y_from0`, false when absent.
    - The Simulate report's `totals.burst_pkts` may be `null`.
- If the shell says `command not found`, open a new terminal or run the `export PATH=…` line the installer
  printed, or run `~/.local/bin/trex-web-gui`.
- A host without internet: the README's [Offline host](../../README.md#offline-host) section.
- A first stream, step by step: [docs/howto-first-stream.md](../howto-first-stream.md).

## Supported

- TRex v3.08 in stateless mode, STL API 5.1 (the passive Monitor also shows what stateful runs publish).
- Python 3.12 or newer; tested on 3.12, 3.13 and 3.14.
- A Linux backend only; any current browser.

## Known limitations

New in 1.5.0:

- **The GUI inventory's and the first-stream HOWTO's screenshots were shot on 1.4.1**: the About screen and every
  status bar in them show `1.4.1`. Inventory shots 49, 56 and 63 still show the Download/Delete and Export/Import
  buttons touching. The EMU HOWTO's screens (`docs/howto/emu-screens/`) were shot on 1.3.1, with the controls' old
  look.
- **A daemon TRex that is still listed 10 s after the stop was sent can be taken for a hand-started one** if it
  still answers on the command port. The check runs only when two or more TRexes were listed before the stop.
  The stop then keeps Control's session, Control sees a loss, and the Run tab may name the daemon's own process.
- **A stop whose confirmation was lost** (the daemon stopped answering) keeps Control's session; if TRex did stop,
  Control then sees a loss, not a planned stop.
- **Force stop of this backend's own run is offered only through the API**; the Run tab shows Force stop only
  while this backend holds no run.
- **Two kinds of Dashboard setting.** The chart series, metrics and intervals, the columns, history and full width
  are kept per browser and are not part of a test setup. The Overview's interval, layout, tab and Y axis are part
  of a test setup and reset on a new connection.
- **Density is per browser** and is not part of Export settings.

Carried over from 1.4.1:

- **A browser clock that is off from the backend's can misread a stateful run's times:** the daemon Run tab's
  "ends in about", and the hint on Control and in the Connect dialog that a stateful run is going.

Carried over from 1.4.0:

- **A planned stop is recognised by host text, not address.** Control on `localhost` and a daemon dialog on
  `127.0.0.1` read as a loss, not a planned stop; the stop's command port must equal Control's.
- **The automatic reconnect follows only a stateless Start from the daemon dialog** on the same host and command
  port, for the Start timeout plus 20 s plus one connect timeout.
- **The planned-stop record lives in the backend process**: a backend restart forgets it, and a second backend
  never sees it.
- **Force stop cannot stop a TRex the daemon did not start**; stop it on the host.
- **The LLDP Port column shows a name only for a saved label or a confirmed interface name;** otherwise the number.
- **Some screenshot file names still say Studio:** the inventory's shots 113 and 114 (`113-studio-*`,
  `114-studio-*`) and the HOWTO's shots 10 to 17 (`*-studio-*`).

Carried over from 1.3.1:

- **Virtual-function ports are supported as far as one server has shown.** Reset, Clear stats and the Xstats tab
  were fixed on a ConnectX-6 Dx server with two VFs; attributes, service mode, capture, flow stats and latency on a
  VF have not been tried there yet (the probe's `--write` and `--traffic` would show it).
- **A VLAN the host sets on a VF is outside TRex.** The card adds it to what the VF sends and removes it from what
  the VF receives: a capture on the VF does not show it, and a VLAN set in TRex on that port is a second tag, or is
  dropped, depending on the card.
- **TRex's `is_virtual` flag reads false on an mlx5 VF**; the port's description ("Virtual Function") tells it.

Carried over from 1.3.0:

- **An IP option of type 18 (0x12) reads as an "other" option**, since Traceroute is named by its RFC type 82.
  A `.py` profile run under 1.2.0 or earlier built Traceroute as 0x12.
- A document saved before 1.3.0 keeps a read-only options row until a byte edit inside the options or reopening
  it from its bytes.

Carried over from 1.2.0:

- **The shipped `trex-emu` v3.08 crashes** (the server is gone until it is restarted) when a namespace with the
  `ipfix` or `tdl` plugin at namespace level is removed, and when a client with `mdns` is added to a namespace
  without `mdns`. trex-web-gui refuses to load such a profile, and asks for an acknowledgement before it removes
  such a namespace it did not add. `ipfix` on a client, as in the stock `simple_ipfix.py`, is fine.
- **EMU has no authentication and no ownership.** Anyone who can reach port 4510 can read and change every
  namespace, and another tool can change the list under the page. Firewall the port or use an SSH tunnel (the
  README's "EMU exposure" section).
- **A load that fails part-way leaves a partial profile on the EMU server.** The page says so; load the profile
  again.
- **EMU is tested on the AF_PACKET test guest only.** On hardware NICs, TRex may need `--software` with `--emu`,
  and the port may need filtered service mode (mask 29); neither is verified on hardware.

Carried over from 1.1.4:

- **A stopped TRex server is told apart only on the backend's host.** With TRex on another host, or no server
  process seen at connect, a loss still waits for 12 s of silence and says the server may have stopped or the
  network may be down.

Carried over from 1.1.3:

- **The EVPN-VXLAN preset sends the data plane only.** TRex stateless mode holds no BGP session, so no EVPN
  routes are sent, and a switch that admits VXLAN only from VTEPs it learned over BGP may drop the traffic.
- **A GENEVE layer under UDP's default source port, 53, shows as `GENEVE as DNS`** (or `GENEVE as Raw`): Scapy
  reads those bytes as DNS first. Set the source port to any other value.

Carried over from 1.1.2:

- **A command run over `ssh` may not find `trex-web-gui` by name.** With bash and Ubuntu's `~/.bashrc`,
  `ssh <host> trex-web-gui` runs a shell that stops reading `~/.bashrc` before the line that adds `~/.local/bin`,
  so it answers `command not found`. Log in first, or give the full path, `ssh <host> '~/.local/bin/trex-web-gui'`.

Carried over from 1.1.1:

- In the Connect and Payload dialogs the unsaved-changes list opens outside the dialog, so a screen reader that
  honours `aria-modal` may not reach it; the ⓘ notes behave the same way.

Carried over from 1.1.0:

- **Capture summaries read the first 2 048 bytes of a frame.**
  - A DNS response larger than that lists as UDP/Raw in the capture list.
  - The layer tree of a clicked packet still decodes it, up to 9 238 bytes.
- **The packet worker is shared.** The capture viewer's tree and the packet editor use one worker, so a capture
  click can hold an editor call for up to 5 s.

Security posture ([SECURITY.md](../../SECURITY.md) has the detail):

- The backend binds `127.0.0.1` only; there is no `--listen` and no TLS. Reach it from another machine through an
  SSH tunnel.
- A per-launch token gates the API, but any local process of the same user that reads the printed URL can drive
  it.
- `.py` profiles and Scapy field expressions run as code on the backend host, by design (the UI says so).
- Logging out deletes that browser's cookie and closes every open WebSocket of the backend, every tab's. The
  token stays valid until the backend exits, so restart it to revoke a login URL someone else has seen.
- A profile child that calls `setsid()` escapes the process-group kill.
- The TRex daemon on port 8090 has no authentication. Restrict it before using daemon control outside a trusted
  test network.

Known issues carried over from 1.0.0, each **unverified**: seen on the hardware host, with the cause not found.

- **A port left owned after the backend stops.**
  - Once, after a Ctrl+C, the next trex-web-gui was refused a port still owned by the stopped one.
  - **Re-acquire my ports** takes it back.
  - The stop prints `Released port(s) …` or `Releasing port(s) … failed`; please report that line if it happens.
- **`Load failed` on Control.**
  - A request that got no reply (Safari's wording), seen once over an SSH tunnel.
  - The message names the request and asks whether trex-web-gui is still running and the tunnel up.
  - The cause is not known.

Other limitations:

- **Drop rate is TRex's Tx minus Rx over all ports**, so traffic that does not come back to a TRex port reads as
  dropped. It is a loss figure only when the traffic loops back, through a device under test or a cable.
- The Events log is not restored after a page reload.
- On a `linux_based` TRex, a VLAN set and then cleared on a port stops it answering ARP until TRex restarts.
- Service mode is changed per port on Control > Config. The Dashboard's service-mode bar and Capture > LLDP can
  turn it off.

## Deviations

Where trex-web-gui differs from the tools it replaces:

- Keyboard accelerators:
  - built: Ctrl+Shift+C, Ctrl+Shift+P, Esc and Enter, and the stream keys (Ctrl+C/V, Del, Alt+↑/↓);
  - not built: Ctrl+Shift+D;
  - dropped: Ctrl+Q (the browser owns it).
- A real command line replaces the old Java properties: `--server`, `--data-dir`, `--port`, `--monitor`,
  `--monitor-only`, `--daemon-port`. There is no `--listen` (loopback only, above).
- More than one profile on a port is shown read-only; full multi-profile control is planned.
- The Studio routes `/studio` and `/studio/packet` redirect to `/editor` and `/editor/packet`; the API's
  `/api/studio` routes keep their names.
- A `reconnecting` recovery in the session snapshot and the `session` WebSocket message also carries `left_s`, the
  seconds left (never below zero) when the message was built; `deadline` is unchanged.
- One application in the browser instead of three desktop tools; the backend runs on Linux only.
