# trex-web-gui 1.0.0

The first release. trex-web-gui is a web interface for a [Cisco TRex](https://github.com/cisco-system-traffic-generator/trex-core)
traffic generator in stateless mode: traffic control, statistics, packet capture, profile editing and passive
monitoring in one application, replacing the separate `trex-stateless-gui`, `trex-packet-editor` and `trex-qt-gui`
tools. The wheel is `trex_web_gui-1.0.0-py3-none-any.whl`, attached to the GitHub release `v1.0.0`.

## What is in

- **Control**: connect to a TRex server; acquire and release ports; assign `.py`, YAML or JSON profiles; start,
  pause, update and stop traffic, with the Multiplier typed with its unit (`1.5 Mpps`, `10 Gbps`, `25%`, or a bare
  × factor); configure ports (L2/L3, VLAN, IPv6, ARP, service mode, attributes); ping, scan IPv6 neighbours, read
  extended counters; save and re-run multi-port test setups. The Traffic tab shows what is on the port, which is
  what Start sends.
- **Dashboard**: global, per-port, per-stream (PG ID) and latency statistics with charts (legends, a Fit / From 0
  Y axis), CPU and mbuf utilization.
- **Capture**: a live capture monitor with a packet viewer, Wireshark on the backend host, server-side recorders
  saved as pcap, LLDP neighbours.
- **Studio**: a library of stream profiles edited offline (import `.py`, YAML, JSON or pcap; edit streams, with a
  typed Rate box; simulate; export) and a packet editor (layers, fields, payloads, Field Engine, presets,
  templates).
- **Monitor**: a passive view of what a TRex server publishes on its event port, independent of the control
  connection, also as a wall display.
- **TRex daemon**: write a TRex config, start and stop TRex through `trex_daemon_server`, run stateful profiles,
  read its logs.

Before this release, five release candidates were used on a hardware TRex host, and
the findings were fixed in turn. rc4, after rc3: more space under the Dashboard tiles, chart time
labels on one line, ruled columns in the Dashboard tables, help on the empty Streams tab for giving a stream a
PG ID, and a Drop rate tile that says what TRex computes (below). rc4 also says plainly when a server runs in
ASTF mode and logs a failed connect in Events, treats a transmitting port that lost link as running for Stop,
Stop all and stop-first, lets Port name and Description each adopt a label changed elsewhere, starts a new
connection's PG ID charts with nothing tracked, makes `release.py check` fail when the wheel is missing, and drops
`spec 6.5:` from the capture service-mode note. rc5 renamed the project to trex-web-gui (the command, the wheel,
the data directory, the saved-settings export format) and made a very large packet record open in the packet editor
without stalling the worker: only its first 9238 bytes are decoded into layers, the rest is one raw layer, with a
warning, so no packet Studio can build (up to 9238 bytes) is ever capped.
The project was called trex-gui during its pre-releases.

## Install

```
uv tool install --python 3.12 https://github.com/CRinATL/trex-web-gui/releases/download/v1.0.0/trex_web_gui-1.0.0-py3-none-any.whl
trex-web-gui serve
```

Open the login URL it prints; for a browser on another machine it also prints the SSH tunnel command. An installed
release candidate is replaced with `uv tool install --force --reinstall …`; stop its `trex-web-gui serve` first. A
host without internet: the README's [Offline host](../../README.md#offline-host) section. A first stream, step by
step: [docs/howto-first-stream.md](../howto-first-stream.md).

## Supported

- TRex v3.08 in stateless mode, STL API 5.1 (the passive Monitor also shows what stateful runs publish).
- Python 3.12 or newer; tested on 3.12, 3.13 and 3.14.
- A Linux backend only; any current browser.

## Known limitations

Security posture ([SECURITY.md](../../SECURITY.md) has the detail):

- The backend binds `127.0.0.1` only; there is no `--listen` and no TLS. Reach it from another machine through an
  SSH tunnel.
- A per-launch token gates the API, but any local process of the same user that reads the printed URL can drive
  it. `.py` profiles and Scapy field expressions run as code on the backend host, by design (the UI says so).
- A profile child that calls `setsid()` escapes the process-group kill.
- The TRex daemon on port 8090 has no authentication; restrict it before using daemon control outside a trusted
  test network.

Known issues, each **unverified**: seen on the hardware host, with the cause not found.

- **A port left owned after `trex-web-gui serve` stops.** Once, after a Ctrl+C, the next trex-web-gui was refused a port
  still owned by the stopped one; on the test guest the same stop releases it. **Re-acquire my ports** takes it
  back. The stop now prints `Released port(s) …` or `Releasing port(s) … failed`; please report that line if it
  happens.
- **`Load failed` on Control.** A request that got no reply (Safari's wording), seen once over an SSH tunnel; the
  message now names the request and asks whether `trex-web-gui serve` and the tunnel are up. The cause is not known.

Other limitations:

- **Drop rate is TRex's Tx minus Rx over all ports**, so traffic that does not come back to a TRex port reads as
  dropped. The Dashboard and Monitor tile is named `Drop rate (Tx − Rx)` and its tooltip says so; it is a loss
  figure only when the traffic loops back, through a device under test or a cable.
- The Events log is not restored after a page reload.
- On a `linux_based` TRex, a VLAN set and then cleared on a port stops it answering ARP until TRex restarts.
- Service mode is changed per port on Control > Config; the Dashboard's service-mode bar and Capture > LLDP can
  turn it off.
- A saved test setup keeps the Dashboard tab, interval and layout, not its Y axis choice.
- **Screenshots**: the guide's, the inventory's and the walk-through's screenshots were taken on 2026-10-30, on
  the last release candidate; they match this release.

## Deviations

Where trex-web-gui differs from the tools it replaces:

- Keyboard accelerators: Ctrl+Shift+C, Ctrl+Shift+P, Esc and Enter, and the stream keys (Ctrl+C/V, Del,
  Alt+↑/↓) are built; Ctrl+Shift+D is not, and Ctrl+Q is dropped (the browser owns it).
- A real command line replaces the old Java properties: `--server`, `--data-dir`, `--port`, `--monitor`,
  `--monitor-only`, `--daemon-port`. There is no `--listen` (loopback only, above).
- More than one profile on a port is shown read-only; full multi-profile control is planned after 1.0.
- One application in the browser instead of three desktop tools; the backend runs on Linux only.
